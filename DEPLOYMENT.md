# Deploying EventForge

EventForge is configured as a monorepo:

- `server/` deploys as the Express API on Render.
- `frontend/` deploys as the Vite SPA on Vercel.
- MongoDB Atlas supplies the transactional MongoDB replica set.

## 1. Prepare MongoDB Atlas

Create an Atlas database user with access only to the `eventforge` database, then copy the SRV connection string. Replace the username, password, and database name before adding it to Render:

```text
mongodb+srv://<username>:<password>@<cluster-url>/eventforge?retryWrites=true&w=majority
```

Atlas must allow network access from the Render service. Use a restricted outbound IP/network rule when available for the chosen Render plan. Do not commit the connection string or any credentials.

## 2. Deploy the API to Render

The root [render.yaml](./render.yaml) Blueprint creates the `eventforge-api` web service from `server/`, runs `npm ci`, starts `npm start`, and checks `GET /health`.

Create a new Render Blueprint from the repository and set these environment values when prompted:

| Variable | Value |
| --- | --- |
| `MONGODB_URI` | Atlas SRV connection string |
| `CLIENT_URL` | Vercel production origin, for example `https://eventforge.vercel.app` |
| `JWT_SECRET` | Generated by Blueprint, or a unique 32+ character secret |
| `BADGE_JWT_SECRET` | Generated by Blueprint, or a unique 32+ character secret |
| `AI_PROVIDER` | `mock` for a no-key demo, or `openai` with `OPENAI_API_KEY` set |
| `PAYMENT_PROVIDER` | `mock` for a no-key demo, or `stripe` with the Stripe values set |

Render provides `PORT`; do not override it. After the first deploy, verify:

```text
https://<your-render-service>.onrender.com/health
```

It should return `{"status":"ok","service":"eventforge-api"}`.

## 3. Deploy the frontend to Vercel

Import the same repository as a Vercel project and set **Root Directory** to `frontend`.

| Setting | Value |
| --- | --- |
| Framework preset | Vite |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | `dist` |
| Environment variable | `VITE_API_BASE_URL=https://<your-render-service>.onrender.com/api/v1` |

Apply `VITE_API_BASE_URL` to Production and Preview as appropriate, then deploy. The committed [frontend/vercel.json](./frontend/vercel.json) rewrites SPA paths to `index.html`, so direct links such as `/events/<id>` continue to work.

## 4. Final CORS step

Copy the final Vercel production URL into Render's `CLIENT_URL`, then redeploy the API. To support a local client or known preview deployment during testing, use a comma-separated list:

```text
CLIENT_URL=https://eventforge.vercel.app,http://localhost:5173
```

Every browser origin must be exact: protocol, hostname, and port. Do not include a trailing slash.

## 5. Production checks

1. Open the Vercel URL and test a direct deep link such as `/events`.
2. Sign in, create an event, and confirm the request succeeds without a CORS error.
3. Confirm `GET /health` returns 200 from Render.
4. If using real AI or payments, set `AI_PROVIDER=openai` or `PAYMENT_PROVIDER=stripe` only after their corresponding secrets are configured.

`VITE_API_BASE_URL` is public by design: it is the API address embedded in the browser bundle. Never put API keys, JWT secrets, MongoDB URIs, Stripe secret keys, or OpenAI keys in Vercel variables prefixed with `VITE_`.
